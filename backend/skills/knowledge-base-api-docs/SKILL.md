# 知识库项目 API 文档生成规范

## 使用示例

- “使用 knowledge-base-api-docs，为当前项目生成 API 文档。”
- “按这份 skill 更新文档上传和检索接口说明，核对请求参数与异常处理。”
- “按这份 skill 补充 Agent 问答的流式事件协议和中断行为。”
- “按这份 skill 检查现有 API 文档与代码是否一致。”

## 项目依据与边界

用户提供的 AGENTS.md 确认：Python 3.11、uv、FastAPI、LangGraph、Milvus、MongoDB、BGE-M3。Python 使用类型注解，异步函数保持异步。

本 skill 编写时未读取项目源码，尚未确认应用入口、路由前缀、认证方式、模型库版本、响应包装、流式协议和文档目录。执行时必须先查证，不得把本文件中的场景与模板当成现有接口。

目标是让调用方准确理解已经存在的接口。默认只修改文档；用户明确要求时才修改 OpenAPI 元信息、接口注释或生成脚本。发现行为与声明不一致时记录差异，不擅自修复业务实现。

遵循最小修改原则，不重构模块、不改变函数接口、不删除异常处理、不修改 .env、不写入或输出密钥。

## 工作流程

### 1. 确认范围与既有约定

1. 阅读适用的 AGENTS.md，查看工作区已有改动，保护用户正在修改的内容。
2. 优先使用 rg 查找应用入口、路由注册、模型、依赖、鉴权、中间件、异常处理、测试和已有文档。排除虚拟环境、缓存与第三方代码，不读取 .env 或凭据文件。
3. 阅读依赖清单、锁文件和已有生成脚本，确认实际库版本与命令；不得凭经验引入新工具或升级依赖。
4. 优先沿用现有文档目录与格式。没有约定时，将 Markdown 文档放在 docs/api/API.md；接口较多时按实际业务模块拆分并创建索引，避免同时维护重复的完整说明。
5. 确认需要说明的是全部业务接口、某个模块还是本次变更。范围明确时直接执行，不因文档生成新增审批步骤。

### 2. 盘点真实接口

从实际应用入口追踪 include_router、挂载应用及条件注册，组合各级前缀，得到对外路径。不能只凭装饰器局部路径生成清单。

对每个接口分析：

```text
应用入口 / 路由注册
  → HTTP 方法、完整路径与路由元信息
  → 参数、请求模型、依赖和鉴权
  → 处理函数 → 服务 / 工作流 / 数据访问
  → 响应序列化、异常处理与中间件
```

- 记录实际 HTTP 方法、路径、业务分组和用途；处理 operationId 或路由名称重复问题时先记录，不默认改代码。
- 检查被依赖注入或中间件引入的请求头、权限、错误与响应；不要只阅读处理函数。
- 区分正式业务接口、健康检查、管理接口、框架文档入口及未启用路由。默认不向对外文档暴露内部接口。
- 对隐藏于 OpenAPI 的接口，依据任务范围与实际注册情况决定是否记录，明确其可见性；不要将“未进入 OpenAPI”解释为“不能访问”。
- 不根据 Milvus、MongoDB 或 LangGraph 的能力推测存在对应 HTTP 接口；只记录应用实际暴露的能力。

### 3. 建立证据与核对差异

每个接口在维护文档或生成记录中保留路由、模型及关键处理逻辑的源码位置。仓库内优先使用相对链接；外发版本按需省略内部路径，但保留内部可追溯记录。

分别核对以下证据：

- 路由与模型声明：参数类型、校验、响应模型及 OpenAPI 元信息。
- 实际代码：默认值、序列化、状态码、错误转换和工作流事件。
- 已有测试或安全验证：可观察行为是否与声明一致。
- 实际导出的 OpenAPI：机器可读契约是否完整、是否存在遗漏。

证据冲突时列出“声明 / 实现 / 已验证结果 / 待确认项”，不要静默选择一种说法。只有执行过的验证才标为已验证；静态阅读不足以证明运行时行为。

优先使用已有 OpenAPI 导出方式。仅在确认应用导入和生命周期不会引发不必要的数据库连接、外部调用或数据写入后，才在受控环境中执行导出。无安全运行条件时继续静态分析，并明确导出未执行。

### 4. 生成文档并验证

按下文模板写入实际事实，未知项明确标记“待确认”并附缺失证据。不要为填满模板编造字段、错误码或协议。

先更新接口事实，再同步索引、交叉链接和示例。文档与生成的 OpenAPI 若同时交付，说明各自职责及生成来源，不手工维护相互矛盾的契约。

## 文档结构

首页或单文件开头包含：

- 文档范围、适用环境和已确认的 API 版本；项目没有版本机制时如实说明，不自行定义 v1。
- 基础 URL 占位符，以及代码确认的完整路由前缀。生产地址仅使用已授权、已确认的信息。
- 鉴权方式、通用响应与错误约定；没有统一包装时明确说明各接口按自身响应结构返回。
- 接口清单：业务分组、方法、路径、用途和详情链接。
- 通用规则：实际支持的时间格式、分页、排序、文件限制和流式访问方式。
- 验证方式、未确认项及本次涉及的契约差异。

### 单接口模板

```markdown
## <接口名称>

- 方法与路径：<实际方法> <完整路径>
- 用途：<调用方可完成的任务>
- 鉴权与权限：<已确认机制；无鉴权仅在有证据时填写>
- 内容类型：<请求与响应的实际媒体类型>
- 前置条件与副作用：<读取、创建、更新、删除或任务启动的真实影响>

### 请求参数

| 位置 | 字段 | 类型 / 格式 | 必填 | 默认值 | 约束与说明 |
| --- | --- | --- | --- | --- | --- |
| <path/query/header/cookie/body/form/file> | <实际字段> | <实际类型> | <是/否> | <实际默认或无> | <边界、枚举和语义> |

### 成功响应

<实际状态码、媒体类型、响应结构；按需添加字段表和示例>

### 错误响应

| HTTP 状态码 | 业务码（若存在） | 触发条件 | 响应结构 | 调用方处理 |
| --- | --- | --- | --- | --- |
| <实际值> | <实际值或不适用> | <代码证据支持的条件> | <真实结构> | <可行处理> |

### 调用示例

<符合该接口模型、使用占位凭据和虚构业务数据的最小请求与响应>

### 特殊行为

<仅填写适用的异步任务、流式事件、重试、幂等、分页或一致性语义>

### 来源与验证

<源码相对链接、执行过的检查和未确认项>
```

不适用的小节可省略。仅当类型与必填关系易混淆时增加解释，不把通用框架教程复制进每个接口。

## 请求与响应描述规则

- 分别记录 path、query、header、cookie、JSON body、form 和 file 参数；注意依赖引入的参数。Header 的标准大小写不作为额外业务限制。
- 必填、可为 null、可省略和默认值分别描述，不能把“可为 null”直接写成“选填”。
- 核对字段别名、请求与响应名称、嵌套结构、枚举、长度、范围、精度及自定义校验；以实际版本和配置为准。
- 区分模型类型与线上 JSON 表示，例如日期、时间、标识符、Decimal 和二进制内容；示例按真实序列化格式填写。
- 检查 response_model、排除字段、排除 null/default、别名输出，以及直接返回 Response 的路径，避免把数据库对象原样当作 API 响应。
- 成功响应逐一记录实际状态码；无响应体的接口不附加虚构 JSON。二进制、下载、重定向与流式响应分别说明。
- 文档示例使用虚构标识符与内容，不复制真实用户消息、私有文件路径、内部地址或生产数据。
- 不默认加入 code、message、data 包装，也不默认使用 Bearer、分页字段或某套业务错误码。

## 错误、权限与重试

- 追踪 HTTPException、验证错误、自定义异常处理、中间件及服务层错误映射，记录调用方最终看到的响应。
- 验证错误结构与状态码须检查实际处理器；不能仅套用框架默认行为。
- 分开描述身份验证失败、权限不足、资源不存在、参数错误、任务冲突和内部失败，前提是这些分支在项目中存在。
- 只公开稳定且面向调用方的错误信息，不把数据库异常、堆栈或连接参数写进示例。
- 对 token、session、API key 等只展示占位值与实际传递位置，不推测有效期、刷新方式或权限粒度。
- 仅在代码、测试或既有契约支持时声明幂等性、自动重试、限流、超时和取消能力。请求超时不等于服务端未执行；有副作用的请求不得一概建议重试。

## 项目业务场景

以下规则只对实际存在的接口应用，不据此新增 API。

### 知识库与文档管理

- 说明标识符的真实含义与作用域，及创建、更新、删除对文档、索引和会话的实际影响。
- 上传说明真实媒体类型、文件字段名、是否支持多文件、类型与大小限制，以及其他表单字段；不要把客户端限制当成服务端保证。
- 区分请求接收成功、文件上传完成、解析完成、索引可用。只使用后端实际状态枚举，说明状态查询方式与终态。
- 后台任务说明任务标识、查询入口、失败信息和实际重试 / 取消能力；没有查询或取消接口时如实记录。
- 说明同步与异步边界及已确认的一致性行为，不承诺跨 MongoDB 与 Milvus 的原子性或立即可检索。

### 检索

- 记录查询文本、知识库范围、过滤条件、返回数量和阈值等实际字段，以及默认值与边界。
- 说明结果排序、片段、来源、元数据和评分的真实语义；未经确认不把相似度写成概率、准确率或置信度。
- 分页按实现描述：页码、offset/limit 或 cursor；核对起始值、最大值、总数和下一页语义，不强加统一分页格式。
- 区分合法查询但无结果与请求失败。引用、页码、文档定位等只记录真实字段。
- BGE-M3、Milvus 等内部实现仅在解释实际字段或已公开行为时提及，不增加前端直连说明。

### Agent 问答与流式协议

- 核对会话标识、消息角色、历史上下文、知识库范围、回答与引用的真实字段；不要照搬其他聊天 API 的模型。
- 从路由及客户端消费逻辑确认传输方式、媒体类型和分帧规则：SSE、NDJSON、WebSocket 或其他实际协议；分块传输本身不是 SSE。
- 对 SSE 记录实际使用的 event、data、id、心跳与结束标记；HTTP chunk 不等于完整事件，调用方应按协议分帧。
- 对 WebSocket 说明连接鉴权、双向消息、错误消息、关闭码及连接清理；只描述已实现的字段和行为。
- 制作事件表：实际事件名、payload、触发条件、是否终态、前端处理。区分增量内容与完整快照，说明拼接或覆盖规则。
- 说明响应开始前的 HTTP 错误和响应开始后的流内错误；不得承诺发送数据后还能改成另一 HTTP 状态码。
- 核对结束、用户断开、任务失败、超时与取消的实现。连接关闭不自动等于后端工作流取消。
- 只有存在恢复机制时才说明断点续传、重连或事件重放，核对重复消息和去重语义。
- LangGraph 内部状态不自动成为公共事件；不把内部推理、工作流调试数据或模型隐藏思考写成对外协议。
- 给出符合实际分帧规则的完整最小交互示例，覆盖成功结束以及已实现的错误或中断行为。

## 示例与验证要求

- 示例必须与模型、媒体类型、鉴权位置和响应一致；请求与响应中的虚构 ID 保持关联。
- 优先沿用项目已有示例风格。提供 curl 或 HTTP 示例时确保 JSON、multipart 和流式消费方式正确，并注明适用终端；Windows PowerShell 示例需避免 shell 别名与引号歧义。
- 不把调用示例直接对生产执行。验证默认使用已授权的本地或测试环境；读取优先，数据写入或删除仅在任务已授权的隔离数据范围内进行。
- 校验链接、方法与完整路径、参数位置、必填/null/default、枚举、状态码、媒体类型及示例的一致性。
- 使用现有测试或工具验证关键契约；仅在有必要覆盖文档涉及的真实行为差异时补充测试，不新增只复述文档内容的测试。
- 涉及 Python 命令或依赖管理时使用 uv 与项目既有配置，不使用 pip 直接修改依赖，不修改异步函数与接口以方便生成文档。
- 对已有 OpenAPI 导出检查完整性、schema 引用与目标接口覆盖，记录实际使用的工具和结果。文档更新时间不等于接口版本。
- 工具或服务不可用时继续可完成的静态工作，并明确区分已生成、已核对、已运行验证和未确认事项。

## 交付说明

交付时用简洁中文说明：

1. 修改了哪些文件及原因；列出文档覆盖的实际接口范围。
2. 是否影响函数接口、API 契约、运行时行为或 OpenAPI 元信息。
3. 如何验证、实际结果、发现的差异和未验证项。

只创建或更新本 skill 时，检查 YAML 元信息、触发范围、项目依据、模板和规则一致性；不为规范文件启动数据库、修改业务代码或生成未经代码核对的接口文档。
