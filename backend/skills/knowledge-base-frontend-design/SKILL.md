# 知识库项目前端页面设计规范

## 使用示例

- “按 knowledge-base-frontend-design 规范设计知识库列表页。”
- “按这份 skill 优化文档上传页，先检查实际上传与处理状态。”
- “按这份 skill 审查问答页的移动端布局、引用展示和流式错误状态。”

## 目标与适用范围

以清晰、克制、可操作的知识库工作台为设计方向。让用户容易完成查找知识、管理资料和阅读回答等已被项目支持的任务。业务内容优先于装饰，优先复用项目已有页面与组件。

本次规范的项目依据是用户提供的 AGENTS.md：FastAPI、LangGraph、Milvus、MongoDB、BGE-M3。未通过本地代码确认前端框架、组件库、页面路由、认证方式及接口协议；实施时必须先检查，不得把下文业务场景和视觉默认值当作现有实现。

仅在任务涉及前端页面设计、实现或审查时应用。本 skill 不授权新增业务能力、数据库结构或后端接口。

## 执行顺序

1. 阅读适用的 AGENTS.md；查看工作区修改，保护用户已有改动。不要读取或修改 .env，不输出密钥。
2. 查找前端入口、依赖清单、路由、页面、布局、组件、样式变量、API 客户端和已有校验命令。优先使用 rg；工具不可用时明确说明无法验证的部分。
3. 分析目标页面的调用链：路由 → 页面 → 组件 → 状态管理或数据逻辑 → 请求封装 → FastAPI 路由与响应模型。涉及问答时继续检查实际流式协议、事件处理、错误分支与清理逻辑。
4. 记录已经确认的框架、组件库、设计变量、接口字段、页面状态及现有约束；将未知项与建议项分开。
5. 明确主要用户任务、页面信息层级、核心操作及状态变化。已有设计体系优先；只补充本次缺失的规则。
6. 做最小范围修改，复用布局与组件。不要借页面设计重构无关模块、替换框架或批量引入依赖。
7. 按本文件的验收项检查实际页面，并报告文件变更、原因、接口影响和验证结果。

用户给出的明确视觉要求优先于本文件的默认值。常规可逆页面修改在既有授权内直接完成；只有确实缺少影响任务正确性的信息时才询问。

## 视觉与信息层级

- 使用统一的应用外壳：已有导航、页面标题区、工具区、主内容区。新增页面沿用相邻页面的结构。
- 页面标题说明当前任务；必要时附一行简短说明。主操作与标题或工具区对齐，一个操作区域只突出一个主操作。
- 列表强调扫描效率；详情强调阅读；问答强调问题、回答和来源。不要把全部内容都套进卡片。
- 界面文案默认使用简体中文，术语一致。操作使用具体动词，如“上传文档”“重试”“查看来源”。优先沿用项目已有命名。
- 避免大面积渐变、装饰性图形、过度阴影和无意义动画。没有业务数据支撑时，不生成统计数字、趋势图或功能入口。

### 视觉默认值

只有项目缺少对应规范时才使用以下值；在已有主题变量中实现，避免逐页硬编码。新增语义变量时沿用当前项目命名方式。

| 项目 | 默认值 | 用法 |
| --- | --- | --- |
| 主色 | #2563EB | 主按钮、当前项、可操作链接 |
| 页面背景 | #F8FAFC | 工作区背景 |
| 内容表面 | #FFFFFF | 表格、表单、详情区域 |
| 主要文字 | #0F172A | 标题与正文 |
| 次要文字 | #475569 | 描述、时间、辅助信息 |
| 边框 | #CBD5E1 | 输入框及区域边界 |
| 成功 / 警告 / 错误 | #15803D / #B45309 / #B91C1C | 配合图标与文字表达状态 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 px | 基于 4 px 统一节奏 |
| 圆角 | 控件 6 px、内容容器 8 px | 与已有组件保持一致 |
| 字体 | 系统无衬线中文字体栈 | 不为视觉优化引入远程字体 |
| 字号 | 正文 14–16 px、辅助 12–14 px、标题 20–24 px | 长回答优先 16 px |
| 行高 | 界面 1.5、长文本 1.65–1.8 | 确保中文可读性 |
| 控件高度 | 桌面约 36–40 px、触屏约 44 px | 保留舒适点击区域 |

颜色仅为起点，实际组合必须检查对比度。普通文本目标至少 4.5:1；大字号文本和关键控件边界目标至少 3:1。不要靠颜色单独区分结果、选中状态或错误。

## 布局与响应式

- 优先继承现有断点。缺少规范时，以 768 px 和 1200 px 作为初始断点，再根据内容验证。
- 宽屏支持导航与主内容并排；中等屏幕收拢次要面板；窄屏使用单列，导航与来源面板按需展开。
- 页面边距建议桌面 24 px、窄屏 16 px。长回答正文宽度建议控制在约 720–840 px，避免整屏长行。
- 页面整体不出现非预期横向滚动。表格和代码块可在自身容器内横向滚动；长文件名、长链接需要换行或截断并提供完整查看方式。
- 操作按钮在窄屏可换行或进入明确的操作菜单，不隐藏必需操作。固定输入区不得遮挡正文、错误提示或键盘焦点。
- 验证至少覆盖 375 px、768 px、1440 px 宽度，以及浏览器缩放到 200% 后的关键流程。

## 通用组件和交互

### 按钮、表单与弹窗

- 使用项目现有组件；保持尺寸、图标、间距和交互行为一致。图标按钮必须有可访问名称。
- 请求中展示真实加载状态并防止重复提交；禁用操作时说明原因。不要用假进度代替实际进度。
- 表单提供可见标签、必填标识、格式说明及字段附近的错误信息；失败后保留用户输入。
- 删除等破坏性操作需要明确对象、影响范围和确认按钮文案；单项与批量操作沿用现有业务权限和行为。
- 弹窗管理初始焦点、Tab 循环和关闭后的焦点恢复；遵循组件现有 Esc 行为，避免意外丢失未提交内容。

### 列表与表格

- 让名称或标题成为主要识别信息；状态、时间与操作列保持稳定。只显示已存在且对任务有用的字段。
- 分页、搜索、排序、筛选与批量选择遵循实际接口能力。区分“没有数据”和“筛选后没有结果”。
- 更新或刷新时尽量保留查询条件、选择状态和阅读位置；避免无理由整页清空。
- 仅在用户要求或实际性能问题支持时增加虚拟列表等复杂方案，不为设计规范引入额外架构。

### 页面状态

每个涉及数据的区域按需覆盖以下状态，不只设计成功页面：

| 状态 | 展示与动作 |
| --- | --- |
| 首次加载 | 稳定骨架或加载提示，避免布局跳动 |
| 后台刷新 | 保留旧内容，局部显示更新状态 |
| 无数据 | 说明当前为空；仅提供已经支持的下一步操作 |
| 无搜索结果 | 展示查询条件，提供调整或清空筛选入口 |
| 局部失败 | 失败区域说明原因并提供可用重试入口，保留其他内容 |
| 请求超时或断网 | 给出可理解提示，保留输入；遵循现有重试策略 |
| 无权限 | 沿用实际鉴权处理，不伪造可访问内容 |
| 成功 | 就近更新状态，必要时使用短提示，避免重复弹窗 |

## 知识库业务页面

以下场景只在代码或本次明确需求已支持时应用；不得为满足规范自行补齐产品功能。

### 知识库与文档管理

- 知识库列表突出名称、用途及已存在的管理操作；数量和更新时间必须来自真实数据。
- 文档列表展示实际返回的文件名、状态及必要元信息。上传类型、大小、数量限制与服务端校验一致。
- 上传、解析、索引等状态只能映射实际接口状态。上传请求成功不能直接显示“可检索”；后端未提供阶段信息时使用中性提示。
- 失败提示区分客户端校验、上传失败与后端处理失败；重试只调用已有能力。
- 只有接口提供真实进度时才显示百分比；长任务按照现有轮询或事件机制更新，并清理定时器与订阅。
- 文档预览、分块、元数据或索引详情只展示实际可用字段，不暴露后端连接信息或内部敏感配置。

### 检索结果

- 搜索框清楚表达查询目标；筛选器使用实际支持的知识库、文档等条件。请求中保留查询内容。
- 结果按后端返回语义排序；展示可读片段与可追溯来源，只有已有预览或跳转能力时才提供入口。
- 未确认含义的分数不显示为“准确率”或“置信度”；需要展示时保留实际指标名称和语义。
- 高亮关键词与展示片段时进行安全转义；不将接口返回的文本直接作为任意 HTML 渲染。
- 不在前端直接调用 Milvus、MongoDB 或 embedding 服务。通过项目现有请求封装访问已授权 API。

### Agent 问答

- 用户消息、回答、状态提示和引用来源有清晰层级。发送区提供明确按钮；快捷键沿用项目习惯，并尊重中文输入法组合输入。
- 如现有协议支持流式输出，使用真实事件更新内容；检查分片、结束、错误、断开与重连的实际处理，禁止模拟流式效果来代替接口。
- 状态名称来自已确认的服务端事件，不根据前端计时伪造“正在检索”或 Agent 步骤，不展示模型内部推理。
- 用户向上滚动阅读后不强制跳到底部；接近底部时随新内容滚动，必要时提供返回最新内容按钮。
- 只有存在取消机制时才提供“停止生成”；区分停止前端接收与取消后端任务，不承诺未实现的行为。
- 流中断时保留已接收回答并标明未完成；防止旧请求覆盖新会话，切换或卸载时释放连接和监听器。
- Markdown 使用项目已有安全渲染方式；代码块独立滚动，复制反馈简短明确。引用只能来自真实响应，禁止编造来源、页码或原文。
- 后端未提供引用时明确处理为无来源状态，不把无引用回答包装成已验证知识。

## 可访问性与安全展示

- 使用语义化标题、链接、按钮和表单标签；所有核心操作能通过键盘完成，焦点始终可见。
- 错误信息与对应字段关联；异步状态使用适度的可访问提示，流式正文避免每个字符都触发播报。
- 支持减少动画偏好。动效只用于反馈，避免影响阅读和操作。
- 用户输入、文档片段及模型输出一律视为不可信内容；复用已有转义与净化方案，不开启不受控原始 HTML。
- 复用现有鉴权与权限检查；不把后端服务密钥写入代码、前端配置、日志或示例。
- 面向用户的提示说明发生了什么及可采取的动作；内部异常、数据库名称和框架细节只在必要的受控诊断中使用。

## 工程约束

- 优先最小修改，不随意重构已有模块，不修改函数接口或 API 契约，除非用户明确要求。
- 保留已有异常处理、错误文案映射、鉴权及清理逻辑；样式调整不改变已有业务行为。
- 若确需触及 Python：使用 Python 3.11、类型注解及 uv；不使用 pip 直接修改依赖，不把 async 函数改为同步函数。
- 前端依赖遵循项目实际锁文件及包管理工具。纯设计任务优先使用现有依赖，不因为外观偏好换组件库。
- 不修改 .env，不在实现或 skill 示例中写入密钥。

## 验收与交付

根据本次实际改动选取检查，记录通过与未执行项；不为了低风险文案或样式修改新增只复述实现的测试。

- 运行项目已有且与修改相关的类型检查、lint、构建或测试；不得编造命令执行结果。
- 在可用预览中检查真实页面：布局、文字溢出、主次按钮、加载、空态、错误态及窄屏。
- 交互改动检查重复提交、失败重试和键盘操作；流式或异步改动检查中断、页面切换、旧请求竞态及资源清理。
- 使用实际接口或明确标识的模拟数据验证，不把模拟结果当成后端可用性证据。
- 工具、服务或数据不可用时，说明具体未验证项与原因；检查变更范围，避免覆盖用户已有修改。

交付时用简洁中文说明：

1. 修改了哪些文件，以及每项修改的原因。
2. 是否影响已有页面行为、函数接口或 API 契约。
3. 如何验证、实际结果，以及哪些检查未能执行。

仅编写或修改本 skill 时，检查 YAML 元信息、触发范围、项目依据、相对链接和规则一致性；不要求启动业务服务或为了文档变更新增测试。
