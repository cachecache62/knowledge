# 文档下载与删除

接口位于 `api/import_service.py`，默认端口 8000，沿用登录 Cookie 和来源校验。只能操作当前用户在 `kb_import_tasks` 中拥有的任务；其他用户访问与记录不存在均返回 404。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| `GET /documents` | 查询当前用户的真实导入记录，沿用现有筛选和分页 |
| `GET /documents/{task_id}/download` | 下载原始上传文件，保留中文文件名；优先本地，缺失时回退 MinIO |
| `DELETE /documents/{task_id}` | 清理原文件、对应知识数据和备份，软删除文档登记，保留上传者归属 |

`task_id` 为 UUID。下载返回附件流与 `Cache-Control: private, no-store`，不会把本地路径或对象存储凭据返回给前端。下载文件丢失返回 404，存储不可用返回 503。参数错误返回 422；未登录返回 401。

删除成功返回：

```json
{"task_id": "00000000-0000-0000-0000-000000000001", "message": "文档及对应知识数据已删除"}
```

## 删除范围与失败处理

- `pending`、`processing` 状态返回 409，等待完成或失败后再删除。
- 删除 Milvus 切片集合和产品名称集合中对应记录。
- 删除 MinIO 原文件备份；图片目录仍被其他登记文档使用时保留。
- 删除上传任务的本地目录，包括解析中间文件。最终绝对路径必须位于配置的上传根目录之下，并匹配日期和任务 ID；越界路径返回 409。
- 外部清理成功后将 MySQL 登记的 `is_deleted` 更新为 `1`，保留原始记录和 `kb_import_tasks` 上传者归属；同时将 `active_hash` 置空、更新 `updated_at`，释放去重占位并清理进程内任务状态。之后可以重新上传同一文件，新上传会创建独立记录。
- `is_deleted=0` 表示正常，`is_deleted=1` 表示已删除；原导入 `status` 保持不变。列表、总数、下载、重复删除和同名文档检查均排除已删除记录，后台迟到的状态更新也不会覆盖这些记录。
- 这里只保留数据库审计记录，原文件和向量仍按删除流程清理，不提供通过恢复标记找回文件的功能。
- 跨 MySQL、MinIO、Milvus 和文件系统不存在统一事务。部分清理失败时返回 503 并保留登记记录，可能已有部分文件或向量被清理；修复存储后可再次删除，不把失败请求报告为成功。
- 已生成的历史聊天回答不会随文档删除而改写；对象存储若启用了版本保留策略，也不承诺清除底层历史对象版本。

## 新旧数据兼容

首次使用文档登记库时自动补齐三个可空字段：`storage_path`（原文件相对路径）、`object_key`（成功备份的对象键）和 `vector_key`（新向量使用的任务标识），以及 `is_deleted BOOLEAN NOT NULL DEFAULT 0`。已有记录的删除标记默认为 `0`，不清空已有数据；应用数据库用户需要允许增加列。更新代码后重启导入服务，以便重新运行字段检查。

新导入在两个向量集合中写入动态字段 `source_task_id`，按该任务标识更新和删除，避免同名文档相互清理。旧记录通过上传目录的任务 ID 查找原文件，必要时查询备份对象键；不按可能曾使用不同时区的创建时间猜测路径。

旧向量没有任务标识时，仅在没有其他同名登记记录的情况下使用文件标题匹配，并排除带任务标识的新向量。同名旧记录返回 409，防止错误删除其他任务的数据；需要核对归属后迁移旧向量，不能通过忽略错误强制清理。

更新后重启导入服务，确保新上传使用相同的任务标识规则。未修改现有账户时间策略或 `.env`。

