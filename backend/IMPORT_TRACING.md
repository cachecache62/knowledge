# 文档导入路由记录

入口在左侧「资料库 → 导入路由记录」。上传页的任务卡片、文档管理的每行操作也可以进入对应任务的详情。

## 页面功能

- 列表：按文档名称、任务 ID、Trace ID 搜索，按导入状态筛选，支持分页。
- 详情概览：任务 ID、Trace ID、文件类型、导入路线、开始时间、整体状态、总耗时和处理提示数量。
- 节点时序与流程：切换时间线和流程图，选择节点查看上游、状态、耗时、输入、输出、错误和处理提示。
- 文档与参数来源：查看上传用户、知识库范围及文件类型对应的路线。
- 导入结果：查看整体结果、结束时间及错误。
- 正在运行的记录每 3 秒刷新；任务结束、离开页面后停止轮询。
- 导出 JSON：导出该任务已记录的全部节点快照，携带登录 Cookie，按用户校验权限。

## 记录的路线

| 顺序 | 节点 | 主要内容 |
| --- | --- | --- |
| 1 | `upload_file` | 保存原文件、计算文件指纹、登记文档和上传者归属 |
| 2 | `backup_file` | 将原文件备份到 MinIO；失败时记录提示，继续本地导入 |
| 3 | `node_entry` | 检查文件存在及类型，选择 PDF 或 Markdown 路线 |
| 4 | `node_pdf_to_md` | 调用 MinerU 将 PDF 转为 Markdown；Markdown 文件标为跳过 |
| 5 | `node_md_img` | 处理 Markdown 图片 |
| 6 | `node_document_split` | 切分文档内容 |
| 7 | `node_item_name_recognition` | 识别主体名称，生成名称向量并保存 |
| 8 | `node_bge_embedding` | 生成切片向量 |
| 9 | `node_import_milvus` | 写入知识向量集合 |

只有实际执行过的节点才会标为成功。节点抛出异常时记录失败及错误，剩余未执行节点标为跳过；执行正常返回但输出了 warning/error 日志时，节点标为「完成并有提示」。未产生包装记录的节点标为「未记录」，不会推测成功。

## 存储和采集

新增 MySQL 表 `kb_import_traces`，复用现有账户库连接。表以 `task_id` 为主键，另存独立的 `trace_id`、上传用户、知识库范围、文件名、路线、整体状态、起止时间、耗时、节点 JSON 及整体错误。MySQL 时间列采用 `DATETIME(6)`，存储 UTC，接口带时区，前端按北京时间显示。

`utils/import_trace.py` 实现持久化和快照处理。上传确认非重复、完成归属登记后创建记录，并补录实际上传登记时间；重复文件、未通过上传校验或尚未完成登记的文件不创建独立导入轨迹。

`api/import_service.py` 记录上传、备份和任务整体结果；通过 `trace_scope()` 将当前记录器传给工作流。`processor/import_processor/base.py` 在统一节点入口调用 `trace_node()`，在状态被修改前保存输入，执行后保存输出及耗时。通过 ContextVar 隔离并发任务，日志收集只归入当前任务。

记录写入异常会写日志，不改变原有导入成功或失败的处理。数据库暂时不可用时，轨迹可能不完整；记录失败不会把业务导入直接改为失败。

## 接口

均位于导入服务（默认 8000 端口）。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /import-traces` | 当前账号、当前知识库的记录列表；参数 keyword、status、page、page_size |
| `GET /import-traces/{task_id}` | 读取单个任务概览及全部节点快照 |
| `GET /import-traces/{task_id}/export` | 下载上述记录的 JSON 附件 |

未登录返回 401；不存在或非当前账号的任务返回 404；非法 UUID、状态和分页参数返回 422。响应设置 `Cache-Control: private, no-store`。

## 快照边界

输入输出是工作流状态的摘要快照，不承诺记录供应商的逐次原始请求、完整提示词、token 用量或费用。

- 单段文本最多预览 2000 个字符，长内容标记原长度及截断状态。
- 列表最多预览 3 条，超出时记录总数；字典最多预览 30 个字段。
- 稠密向量仅记录维度，稀疏向量仅记录非零元素数，不存储数值数组。
- 单个输入或输出快照限制在 24 KB 内。
- 密码、令牌、密钥、Cookie、签名 URL 参数隐藏；路径状态字段只保留文件或目录名称。
- 用户可复制当前节点快照或导出该任务的全部已记录快照。

## 启用与历史数据

更新后重启导入服务；首次新上传或访问记录接口时自动建表，数据库账号需要建表权限。前端使用开发服务，或在 `fronted` 重新执行 `npm run build`。

从功能启用后的新任务开始采集；此前导入的文档不补造节点时间和输入输出。记录保存在 MySQL，完成任务的历史在服务重启后仍可读取。进程意外退出时保留最后写入的状态，本功能不负责自动恢复或继续执行导入任务。

文档进入回收站不会删除对应的导入记录；恢复文档也不会重跑原导入流程。

## 验证

在 `backend` 执行：

```powershell
.\.venv\Scripts\python.exe -m unittest test.test_import_trace test.test_document_management test.test_api_frontend test.test_database_errors
```

测试使用 SQLite、临时文件及存储和模型替身，覆盖实际上传调用链、节点输入输出、失败路径、备份降级、账号隔离、JSON 导出、脱敏、持久化读取和真实 LangGraph 的上下文传播，不调用真实模型或修改业务数据库。

在 `fronted` 执行 `npm test`、`npm run build`，页面测试执行真实 Vue 组件，覆盖搜索、详情节点选择、流程切换、轮询结束、迟到响应隔离和 JSON 下载。
